# 2026.11.04.11

This is the first stable release of the Data Volume Monitor continuation maintained by **alexphillips-dev**. It brings the development branch to the Stable (`main`) channel, with vnStat **2.14**, the updated Data Volume Monitor artwork, clearer threshold settings, and the reliability fixes described below.

Data Volume Monitor tracks network interface usage in Unraid and can send notifications, stop/start selected Docker containers, disconnect/reconnect VM network links, or run custom functions when configured limits change state. Traffic remains interface based; container and VM matching supplies labels rather than independent application accounting.

## Highlights

- **Updated backend:** bundled `vnstat`, `vnstatd`, and `vnstati` upgraded from 2.12 to 2.14, built from verified upstream source with recorded build inputs and binary hashes.
- **Consistent threshold tables:** eight primary rules and six secondary slots expose thresholds, units, and Docker/VM actions clearly. Primary settings now use the same table style as Secondary, with horizontal scrolling on narrow screens.
- **Clear threshold status:** Disabled is red, Enabled is green, and invalid input is red. These labels describe the entered limit; notification and action switches remain separate.
- **More reliable monitoring:** polling avoids overlapping requests, reports stale or unavailable data, and preserves the last successful measurements when a refresh fails.
- **Safer configuration and recovery:** editor boundaries, save races, backup verification, custom storage paths, service errors, and concurrent notification checks have regression coverage.
- **Deliberate action testing:** Service Check is diagnostic only. Test Configured Actions requires confirmation, and recorded failures can be retried after current configuration and threshold checks.
- **Stable and Development channels:** installed version/channel information is visible in settings. Each channel keeps its own installer, package, and future-update URLs.

## Installation and upgrade

For a new Stable installation, open **Plugins → Install Plugin** in Unraid and enter:

```text
https://raw.githubusercontent.com/alexphillips-dev/Data-Volume-Monitor/main/plugin/dvm.plg
```

The manifest declares Unraid **6.8.3 or newer**, and the packages target **x86_64**. The backend requires compatible host SQLite and GD libraries; it does not replace those host libraries. The declared minimum is not a claim of live testing on every Unraid version.

If you already use this continuation's Development channel, moving to Stable is an **in-place channel switch**. Follow the [channel-switch instructions](https://github.com/alexphillips-dev/Data-Volume-Monitor/wiki/Installation-and-Release-Channels), including the destination-version check. Do not uninstall to switch channels: uninstall deletes plugin settings, backups, and traffic history. Development installations continue checking `dev` until deliberately switched.

If you use the original **`dwdvm`** plugin, follow [Migration from the original plugin](https://github.com/alexphillips-dev/Data-Volume-Monitor/wiki/Migration-from-Original-Plugin) first. Stop the old service, copy configuration/scripts and the newest stopped database outside the old plugin's directories, and verify those independent backups before removal. The original and continued plugins must not be installed together. This release does not automatically migrate the old plugin identity.

After updating, refresh the settings page and check **DVM Version / Channel** and **DVM Backend**. Review saved interface selections, thresholds, and action switches before running configured actions.

## Validation and host acceptance

The release is qualified with the repository's Linux validation entry point: Python regressions, PHP and JavaScript fixtures, syntax/ShellCheck checks, tracked-file checks, backend source/signature and binary checks, channel checks, exact package contents and permissions, and deterministic package rebuilding. The Python suite contains **142 tests**; PHP and JavaScript fixtures run separately in the same validator.

Backend fixtures exercise all three executables, all six PNG output modes, the report formats, structured threshold boundaries, custom paths, and preservation of a database created by vnStat 2.12. Primary-table fixtures cover all eight rows and 48 fields through simulated Apply/reload. Browser simulations cover desktop and phone widths with light and dark fixture styles.

Automated fixtures do **not** establish live Unraid installation, native theme integration, real Docker/libvirt actions, or reboot persistence. Those observations remain separate in the [Host acceptance checklist](https://github.com/alexphillips-dev/Data-Volume-Monitor/wiki/Host-Acceptance). Back up important history before migration or channel changes.
